# 004. 資料ノートをリポジトリに置き、テストは形だけを検査する

- 日付: 2026-09-18
- 対象: `docs/research/*.md`、`tests/*.test.ts`

## 決定

各講座の出典つき資料ノート（Opus サブエージェントが調べ、URL を行末に付けたもの）を `docs/research/` に置く。本文はこのノートの範囲で書き、ノートが「未確認」「諸説あり」「Wikipedia のみ」とした項目は本文でも `<Note kind="unverified">` か「要裏取り」で書く。

テストが検査するのは、画像の記録・用語集の形・ʻokina の文字種・本文の描画・確認問題と出典の存在だけで、**内容の正しさは検査しない**。正しさは「資料ノート → 執筆 → 別モデルによる敵対的検証」の手順で担保する。

## 背景

設計レビューの最大のリスク指摘が「テストは形しか見ないまま一晩に33本が公開面へ出る」だった。内容をテストで捕まえる方法は無いので、根拠を残して人と別モデルが読めるようにした。

## 比較した代替案

| 案 | 却下理由 |
|---|---|
| ノートは scratchpad に置いて捨てる | 後日「なぜそう書いたか」を辿れない。資料ノートは本文の脚注の役を果たす |
| 各段落に出典 URL を埋め込む | 読みにくい。レッスン末の `<Sources>` に節ごとの参照を書き、細部はノートで辿る |

## 検証

執筆後、3班（Opus）に「本文と資料ノートの食い違い・未確認の断定・綴り」を探させ、指摘を反映した（結果は README の記録と git log）。
