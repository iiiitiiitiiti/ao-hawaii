# 011. スマホ表示を短くする — 本文は変えず、畳む・流す・縮める

- 日付: 2026-09-18
- 対象: `src/mele/MeleBodyView.tsx`、`src/widgets/{Terms,Sources,Quiz,BackToTop}.tsx`、`src/lesson/LessonToc.tsx`、`src/styles.css`

## 決定

スマホ（幅 480px 以下）でのスクロール量を、本文（MDX・曲データ）に手を入れずレイアウトだけで減らす。

1. 曲ページの逐語注は、語と意味を1行の札にして横に流す。スマホでは既定で行訳だけを出し、行ごとの「語注」ボタンで開く（全体トグルはそのまま）
2. レッスン末尾の用語ボックスと出典は `<details>` にし、スマホでは閉じた状態で出す（デスクトップは開く）。確認問題は1問ずつめくる
3. リード文の直後に h2 の目次を置き、スクロールしたら右下に「上へ戻る」を出す
4. スマホでは `html` を 87.5%（14px）にし、本文も 1rem に落とす。パスワード入力欄だけ 16px を保つ（iOS Safari の拡大を防ぐ）

実測（幅 390px）: 曲ページ 9,852px → 3,766px、ʻŌlelo Lesson 07 15,640px → 10,942px。

## 背景

持ち主の依頼「スマホでのスクロールを減らしたい」。Windows セッションが本番を実測して案を出し、持ち主が上の4点を選んだ。

## 比較した代替案

| 案 | 却下理由 |
|---|---|
| 曲ページの「成り立ち」も畳む | 持ち主が採らなかった（歌詞より先に読む前提の節） |
| サイトヘッダーとレッスン見出しを詰める | 持ち主が採らなかった（効果が小さく、読みにくくなる） |
| 目次をビルド時に remark で生成する | 実行時に h2 を拾う方が単純で、MDX の見出しに id を付ける処理も同じ場所で済む |
| 用語・出典を常に閉じる | デスクトップでは縦の余裕があり、開いている方が読みながら参照できる |
