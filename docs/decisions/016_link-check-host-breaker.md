## 016. リンク検査は、続けて届かないホストを打ち切って要目視にまとめる

- 日付: 2026-09-28
- 対象: `scripts/check-links.mjs`、`.github/workflows/links.yml`

### 決定

同じホストで接続不能が3本続いたら、そのホストの残りは叩かずに「要目視」へ1行でまとめる。1分後の再試行も並列で回す。ジョブ全体には15分の上限を置く。

### 背景

GitHub Actions の一部のマシンから wehe.hilo.hawaii.edu（約190本）へ接続できない回があった。1本あたり最大約78秒の時間切れを待ったうえ、疑わしい200本超を直列で再試行したため、検査が出力なしで数時間続いた。手元では毎回1〜2分で終わる。

### 比較した代替案

| 案 | 却下理由 |
|---|---|
| 同じホストへの同時接続を2本に絞る | 絞っても応答しない回は応答しなかった。手元の検査も1分半から4分へ遅くなった |
| 時間切れを短くする | 応答の遅い正常なサイトを「切れ」と誤判定する。190本分の待ち時間は残る |
| 15分の上限だけに頼る | 打ち切られた回は結果が何も残らない |

### 影響範囲

- 3本以上のリンクを持つホストが丸ごと落ちても、ジョブは失敗しない（要目視に出るだけ）。受け入れ済みの割り切り
- 2026-09-28 の検証では、GitHub 側マシンの通信不調で、リンクが1本だけのホスト4つを「切れ」と誤判定する回が残った（手元ではすべて 200）

### 検証

- 手元で wehe.hilo を応答なしにした模擬実行: 1分57秒、切れ 0、wehe.hilo は要目視に1行
- GitHub 上の2回: 2分半（切れ 0）と4分（上記の誤判定4件）
